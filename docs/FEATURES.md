# KCLOTH 功能總覽

> 截至 **2026-10-25**（repo `e2626a3`、規則版本 `2026-10-25.4`）
> 網站：https://jonwenjen.github.io/Kcloth/　｜　Repo：https://github.com/jonwenjen/Kcloth

KCLOTH 是 Robin 的 MUSINSA 男裝選物系統。每月 15 日自動跑一次分析，範圍包括 MUSINSA 韓國站與 Global 台灣站。分析時會考慮身形（175cm／75kg、肩 44、胸 48、腰 43.5）、黃偏黑膚色、「43 歲穿出 35 歲感」的目標，以及膠囊衣櫥的缺口。挑出的單品附評分、尺寸建議、排雷數據與價差，結果發布成手機優先的靜態網站。

## 2. 每月自動執行

### 排程

| 項目 | 設定 |
|---|---|
| 名稱 | Kcloth 每月選物分析 |
| 時間 | 每月 15 日 **04:47**（台灣時間；避開整點，提早 13 分鐘） |
| 執行位置 | 綁定 Robin 的 Mac mini（要開機並開著 Claude 桌面 App，因為要用內建瀏覽器抓 MUSINSA） |
| 模型 | `claude-opus-5-5`（有更新的模型時，要到排程設定裡改） |
| 連接服務 | Gmail、Google 日曆、Google Drive、Notion 等 |
| 通知 | 跑完推播到手機 |
| 下次執行 | 2026-11-15 04:47 |

### 流程（`PLAYBOOK.md` 步驟 0–12）

0. **準備**：拉最新 repo，判斷這次是完整、複查還是部分更新。
1. **自我審查**：用這次的模型檢查規則、抓取程式、網站和上月結果，能改的直接改，並記進 run-log。
2. **確認工具**：內建瀏覽器載入抓取器 `KC.*`。
3. **購買紀錄**：讀 Gmail 新訂單和取消信，補資料並逐件判定。
4. **清單同步**：讀「清單同步」Issue，寫入 `data/wishlist.json`，再關閉 Issue。
5. **匯率、折扣、折價券**：抓匯率、讀 Global 首頁的活動、搜尋檔期；必要時建日曆提醒。
6. **潮流**：搜尋 4–6 次，整理成四類並附穿法。
7. **品牌**：整理兩份 20 大清單。
8. **選品**：建 80–150 件候選池 → 排雷 → 入圍分析 → 專家評分 → 尺寸建議 → 價格判斷 → 定出最終名單。
9. **衣櫥分析與穿搭**：找缺口、檢討已購單品怎麼搭、每個溫度帶至少排 2 套。
10. **寫月報並建置**：`kcloth.py build` 必須 0 error。
11. **推送並檢查網站**：push 到 GitHub 後，等 Pages 更新，再用手機寬度確認畫面。
12. **回報**：推播折扣提醒、本月最推 3–5 件、衣櫥缺口、退換建議、方法改進。

### 三種執行模式

| 模式 | 何時觸發 | 做什麼 |
|---|---|---|
| 完整 | 正常月份 | 全部步驟 |
| 複查 | 本月月報 14 天內已經跑過 | 不重抓候選池、不改選品；只複查訂單、清單、檔期、價格與庫存 |
| 部分更新 | Mac 睡眠或 App 沒開，瀏覽器連不上 | 只更新 Gmail、清單、匯率、檔期、潮流、品牌；選品沿用上月，回報時說明原因 |

## 3. 選品規則（`config/rules.json`）

### 3.1 尺寸基準

- **上衣、外套**：韓版 **L（100）**；日系品牌用 Size 2。不會因為腰圍而改推 XL。
- **褲子**：**33 或 34 腰 Short**（褲長 100–102cm）。

### 3.2 版型範圍（平量，cm）

| 類別 | 肩寬 | 胸寬 | 衣長 | 其他 |
|---|---|---|---|---|
| T 恤、針織 | 48–51 | 57–60 | 68–71 | 硬挺微落肩、直筒不收口 |
| 襯衫 | 48–51 | 57–61 | 68–74 | 同上 |
| 外套 | 47–51 | 57–62 | — | 拉鍊款必須雙向拉鍊 |
| 褲子 | — | — | 褲長 99–103 | 前襠 30–32、大腿 34–35.5、褲腳 21–23；以單打褶、微寬直筒優先 |

**下擺收口判定**：上衣下擺平量比胸寬小超過 6cm，就算收口下擺，等同羅紋下擺禁令；差距達 15cm 以上屬嚴重。

### 3.3 分級提醒（取代原本的「直接剔除」）

2026-10-25 起，依 Robin 的指示，條件不符會分三級標示，每條都寫出程度（幾 %、約幾人、超出幾 cm、超出幾 %）。只有第 3 級會被剔除。

| 項目 | 1 注意（−0.1） | 2 警告（−0.3） | 3 嚴重（剔除） |
|---|---|---|---|
| 縮水／起毛球／領口鬆垮（1–3 星） | — | > 5% | ≥ 12% 且 ≥ 8 則 |
| 貼身顯肚（上衣） | — | > 10% | ≥ 25% 且 ≥ 8 則 |
| 薄透（T 恤、針織） | — | > 15% | ≥ 35% 且 ≥ 8 則 |
| 超出尺寸範圍 | ≤ 2.5cm | 2.5–8cm | > 8cm |
| 超出預算 | 0–50% | 50–100% | > 100% |
| Global 溢價 | ≥ 20% | ≥ 50% | — |
| 連肩袖、羅紋下擺、Slim 褲、低腰、薄軟布 | — | 警告 | 下擺差 ≥ 15cm、前襠 < 25cm |
| 單向拉鍊外套 | 注意 | — | — |
| 評論數或同身形樣本太少 | 注意 | — | — |

缺貨和女裝不會列入。

**排序**：`rank = 綜合分 − 各條提醒扣分`；同分時比五項平均。件數不限，上限 100 件。

### 3.4 雙重負評排雷

- **體型過濾**：只看身高 173–177cm、體重 73–77kg 的評論。
- **關鍵字**：
  - 縮水：수축、줄어、shrink…
  - 起毛球：보풀、필링、pilling…
  - 領口鬆垮：목 늘어남…
  - 貼身：몸매 부각、달라붙、뱃살…
  - 薄透：얇아、비침…
- **否定片語先刪再比對**：例如「보풀 없어요」「뱃살 커버」「비침이 없어서」這類正面說法不會被算成負評。
- **抓取量**：排雷抓最新 10 頁（200 則）韓國站評論；要估尺寸的單品抓到 30 頁（600 則）。請求依序送出、間隔 250ms；被擋時冷卻 3 分鐘再試。
- **備援**：韓國站評論被擋時，改用 Global 的英譯評論（含身高體重），門檻不變。

### 3.5 預算與溢價

- 上限：上衣、褲子 **NT$3,000**，外套 **NT$5,000**。值得加價的單品可超出，但必須寫 `budget_reason`。
- 溢價 = Global 台灣價 ÷（韓國價 × 匯率）− 1。**≥ 20% 標紅**，建議等折扣或改買韓國站。
- 沒上架 Global 的單品標「僅韓國站」，預算改用韓國價換算判斷。

### 3.6 顏色與穿搭公式

- **單穿上衣**：炭灰、深霧藍、深鼠尾草綠、深海軍、黑。避免單穿純白和象牙白。
- **疊穿**：內搭深色（炭灰／深海軍／黑）＋外層亮色（冰川藍、霧灰藍、淺卡其灰、燕麥），外搭不扣釦，製造兩條垂直線。
- **單穿白邊**：深色硬挺上衣裡面穿白 T，只在領口露出 1–1.5cm 白邊。
- **倒 V**：雙向拉鍊拉上後，下方拉鍊頭往上拉開 6–8cm（肚臍位置）。

## 4. 單品分析內容

每件入選單品都包含以下內容。

### 專家評分

五位專家各給 1–5 分並附一句評語：

| 專家 | 看什麼 | 草稿權重 |
|---|---|---|
| 材質（面料紡織） | 成分、磅數、厚度 | 25% |
| 版型（打版師） | 以 Robin 身形為準，離規則幾 cm、有沒有踩禁令 | 30% |
| 車工（品管） | 滿意度與評論量 | 15% |
| 保養 | 縮水、起毛球、領口的實際評論比例與洗滌方式 | 20% |
| 機能 | 高雄氣候、彈性、雙向拉鍊、適用場合 | 10% |

另外附**綜合分**、**綜合評語**和**搭配建議**（會引用已購或清單裡的單品）。
分數草稿由 `scripts/draft_items.py` 從原始資料算出，結果可重現，再由 Claude 檢查和改寫。

### 尺寸建議

- **A｜網站尺寸表**：拿各尺寸的實測數字對照 Robin 的目標範圍，給出推薦尺寸與理由。
- **B｜同身形評論**：列出則數、各尺寸各幾人、偏大／正常／偏小的反應。
- **最終建議**：給一個尺寸並說明理由；A 和 B 有衝突時，寫出取捨原因。

### 其他

- **排雷數據**：抓了幾則評論、負評 %、同身形負評 %、貼身 %、薄透 %、商品標示的厚度、資料來源（韓文或英譯）。
- **價格**：Global 售價與原價、韓國價與換算台幣、價差 %、預算狀態。
- **材質與保養**：成分、產地、洗滌方式、評分與評論數、適穿溫度。
- **連結**：Global 台灣站、韓國站、全部評論。

### 清單

- 在單品卡片按「＋ 加入清單」，清單存在手機瀏覽器裡。
- 按「**同步到 GitHub**」會開一個 Issue；在 GitHub 按 Submit 後，15 號的分析就會匯入。清單太長時，改為複製 JSON。
- 每月匯入時會重新檢查清單內單品的價格；已經買了的會從清單移除。

### 溫度穿搭（高雄）

| 溫度帶 | 基本層次 |
|---|---|
| 28°C 以上 | 單穿重磅上衣＋白邊內搭 |
| 24–28°C | 單穿，或薄襯衫敞開外搭 |
| 20–24°C | 深色 T＋亮色襯衫或 Overshirt 敞開 |
| 16–20°C | 深色 T＋針織或雙向拉鍊夾克 |
| 16°C 以下 | 針織＋夾克或大衣 |

每個溫度帶有兩種搭配：「**專家搭配**」來自月報；「**自動配**」用已購＋清單即時組合。

## 7. 購買紀錄

- **來源**：Gmail 裡 `mail.global@musinsa.com` 寄的「Your order has been confirmed」信，另外也查取消和退款信。
- **補資料**：每件補 goodsNo、成分、該尺寸的實測數字，並歸到衣櫥格、角色與適穿溫度。
- **逐件判定**：

| 判定 | 意思 |
|---|---|
| 符合規則 | 可以直接穿 |
| 注意穿法 | 可以穿，但要用特定穿法（例如敞開、內搭深色） |
| 到貨確認 | 先看實物，或洗後觀察 |
| 建議退換 | 違反硬性規則，還能退的話建議退 |

- **隱私**：repo 是公開的，不寫入訂單編號、收件人、地址和電話。

## 9. 工具與檔案

### 指令（`scripts/kcloth.py`）

| 指令 | 用途 |
|---|---|
| `bundle` | 把抓取器和規則打包成 `.cache/collect.bundle.js` |
| `validate YYYY-MM` | 依規則檢查月報 |
| `build YYYY-MM` | 計算溢價、預算、分級提醒和排序；0 error 才寫出 `data/latest.json` |
| `wardrobe` | 列出衣櫥各格的目標、已有、清單和缺口 |
| `check` | 檢查訂單、清單和最新月報 |

### 瀏覽器抓取器（`scripts/collect.js`，在內建瀏覽器內執行）

| 函式 | 用途 |
|---|---|
| `KC.list` | 結構化搜尋，可依關鍵字、品牌、分類查詢 |
| `KC.search`／`KC.brand` | 從搜尋頁、品牌頁取得商品編號 |
| `KC.screen` | 批次快速排雷，回傳精簡欄位 |
| `KC.item` | 單品完整資料：價格、材質、實測尺寸、評論分布、排雷結果 |
| `KC.globalPrice(s)` | Global 台灣價，並判斷是否可買或對台灣不販售 |

### 檔案結構

```
config/profile.json      身形、預算

PLAYBOOK.md              每月執行手冊
CLAUDE.md                給 Claude 的簡要說明
scripts/collect.js       瀏覽器抓取器
```
